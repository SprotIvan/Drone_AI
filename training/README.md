# Донавчання моделі станції (YOLO26n, `bestty.pt`)

Повний шлях: публічні датасети + кадри станції → один чистий датасет →
донавчання в Google Colab → ONNX → Hailo Dataflow Compiler → `.hef` на Pi.

## 1. Завантажити публічні датасети

```bash
ROBOFLOW_API_KEY=... python fetch_datasets.py D:/d/DocumentsFromC/GitHub/drone_training
```

- Ключ береться **лише зі змінної середовища**, ніде не записується.
- Джерела, версії й ліцензії — у `SOURCES` у `fetch_datasets.py`.
  Обрано версії **без аугментації** там, де вони є.
- Джерело з ліцензією **CC BY-NC-SA (некомерційна)** пропускається.
  Додати його: `--include-nc` — лише якщо станція некомерційна.
- Обірване завантаження докачується з місця обриву; повторний запуск
  пропускає вже завантажене.

## 2. Кадри зі станції (фон і перевірка)

У `acoustic_radar/fusion_config.json` на Pi:

```json
"visual": {"frame_record": true, "frame_record_every_s": 1.0}
```

Станція пише в `logs/frames_<час>/`: `*_pub.jpg` (640×480, що бачить
повний кадр), у режимі кропів ще `*_nat.jpg` (рідний кадр), і
`frames.jsonl` — бокси детектора на кожному кадрі. Кадри з боксами
детектора зберігаються завжди (не частіше 1 разу на 0.25 с) — так самі
собою збираються **хибні спрацювання**.

- **Фон (без дрона)** — просто покласти в `drone_training/station/`.
- **З дроном** — покласти поруч `*.txt` у форматі YOLO
  (`0 cx cy w h`, нормовані 0..1). Такі кадри з **окремого дня польотів**
  краще відкласти в `station_val/` для чесної перевірки (див. крок 5).

### Сортування записаних кадрів (`station_frames.py`)

```bash
scp -r pi@192.168.50.1:~/mk_crops/acoustic_radar/logs/frames_<час> drone_training/station_raw/
python station_frames.py sheets drone_training/station_raw/frames_* --out drone_training/station_review
# переглянути station_review/sheet_*.jpg, заповнити station_review/labels.json
python station_frames.py folders drone_training/station_review --out drone_training/station_sorted
# перевірити в провіднику station_sorted/{drone,background,skip}; не згоден — перетягнути файл
python station_frames.py export drone_training/station_review --to drone_training/station \
    --folders drone_training/station_sorted
```

Мітка ставиться **на весь кадр**, не на рамку: `"bg"` — у кадрі **ніде**
немає дрона (дрон у руці поруч із хибною рамкою на колесі робить кадр
дроновим, а як фон він навчив би, що дрон — це фон); `"drone:0,2"` —
рамки 0 і 2 стоять на дроні, інших дронів у кадрі немає; `"skip"` — решта
(дрон без рамки, не видно). `export` пише кадр 640×480 і 6 вікон 640×640
з рідного кадру (`smart_crop.tile_origins`, як у режимі кропів); вікно, що
розрізає рамку дрона, пропускається.

## 3. Синтетичні малі дрони (для далеких цілей)

```bash
python synth_small_drones.py D:/d/DocumentsFromC/GitHub/drone_training --count 2000
```

Вирізає дронів **за маскою** з близьких кадрів на однорідному фоні
(каталожне біле тло, чисте небо) — **лише з класів із роллю `drone`**
(інакше птахи й лайнер потрапили б у синтетику з міткою «дрон»), зменшує
до 12–40 px (переважно 16–32) і вставляє на **фонові кадри станції** з
`station/`. Колір несеться з урахуванням прозорості (premultiplied), тож
край дрона змішується з новим фоном, а не з білим тлом каталогу. Відкидає
вирізки-«картки» (маска заповнює свій повернутий прямокутник на >85% —
фото товару, де дрон надруковано на білій картці), вставки, що після
зменшення стали тоншими за ¾ заданого розміру, і «невидимі» (контраст з
фоном < 12 рівнів). Шум і JPEG — на весь кадр, бокс —
за тим, що після розмиття непрозоре хоча б наполовину. Приклади:
`synthetic_sheet.jpg`. Такі кадри йдуть **лише в train**; чи допомогли
вони — вирішують справжні кадри станції.

## 3а. Фони без дронів і власні фото (раунд 3, `prepare_extra.py`)


- **Фони** (Kaggle, ліцензії перевірено через API): небо/хмари (CC BY 4.0),

  відрізок). Некомерційний набір і набір з невідомою ліцензією пропущено.
- Модель ft_v2 на цих фонах спрацьовувала (≥0.40) на 77 % фото з птахами,

- Фони **не підвищують** частку знайдених дронів — вони прибирають хибні

| Причина | Частка дронів |

- **Синтетика на захаращеному фоні** (`synth_small_drones.py --clutter`):

  погода, птахи), будь-де в кадрі, а не переважно в небі; поріг контрасту

## 4. Зібрати датасет

```bash
python build_dataset.py D:/d/DocumentsFromC/GitHub/drone_training --zip
python build_dataset.py D:/d/DocumentsFromC/GitHub/drone_training --stats-only   # лише статистика
```

Перший прогін ~17 хв (хеші й оцінка копій усіх ~60 тис. кадрів). Далі
хеші беруться з кешу `drone_training/build_cache.json`: `--stats-only` —
~4 хв, повна збірка з `--zip` — ~12 хв (копіювання ~1 ГБ і архів)
на цьому ноутбуці.

`--max-box-area 0.15`: кадри, де найбільший бокс (дрона або птаха) займає
>15% площі (каталожні фото зблизька), не йдуть у навчання — станція ніколи
не бачить їх такими великими. Вони лишаються джерелом для вирізання в
кроці 3. Збирач друкує розподіл довгої сторони боксів (px при 640) по
кожному джерелу.

Результат — `drone_training/drone_dataset/`:
`images/{train,val}`, `labels/{train,val}`, `data.yaml` (1 клас `drone`),
`SOURCES.md` (авторство й ліцензії — CC BY цього вимагає), `stats.json`.

Що робить збирач (кожне правило перевірене на завантажених даних):

- **Класи** — за мапою в `SOURCES` (`fetch_datasets.py`): кожен клас
  кожного джерела має явну роль `drone` / `background` / `drop`. Клас без
  ролі **зупиняє збірку** — мовчазне значення за замовчуванням зробило б
  «фоном» усі 8 132 дрони anti-drone (їхні класи звуться
  `Fixed-wing/Multicopter/VTOL`). `Fixed-wing` там змішаний із
  пасажирським лайнером і пілотажними літаками → такі кадри виключено.
- **Аугментовані копії** — ім'я файлу в Roboflow **не** унікальне для фото
  (`141.jpg` — 23 різні птахи). Копії групуються за іменем лише в train
  проєктів із `AUGMENTED_TRAIN` (там кожне ім'я рівно ×3); лишається
  найчистіша копія (найменше імпульсного шуму й чорних кутів від повороту).
- **Кадри без боксів** з публічних наборів виключено: у вибірці з 24 три
  містили нерозмічений дрон або літак. Фон беремо зі станції.
- **dji-drones не йде в навчання** (`EXCLUDED` у `build_dataset.py`):
  аугментацію «вшито» у файли ще до завантаження — приблизно половина
  вибірки перевернута на 90–180° (небо внизу), розмазана після повороту
  або сильно зашумлена. Для вирізок синтетики його використано.
- **Великі об'єкти** (`--max-box-area`) — і дрони, і птахи.
- **Дублікати** — однаковий хеш кадру **і** однакові бокси. Без боксів
  відео зі статичної камери злилося б в один кадр.
- Ділить train/val **кластерами схожих кадрів** (щоб майже однакові кадри
  одного відео не опинились і в навчанні, і в перевірці) — **всередині
  кожного джерела**: хеш не розрізняє сцени з чистим небом (кадри різних
  джерел мають однакові хеші), і зв'язки між джерелами склеювали 16 511 з
  21 883 кадрів в один кластер. Кожне джерело віддає у val ~10% своїх
  кадрів із невеликих кластерів; довгі «небесні» ланцюжки лишаються в
  train. Фото більші за 1280 px зменшуються.

`--zip` пакує вміст теки (не саму теку) в `drone_training/drone_dataset.zip`.

1. У Google Drive створити `MyDrive/drone_training/` і покласти туди
   `drone_dataset.zip`, `bestty.pt` і wheel Hailo DFC
   `hailo_dataflow_compiler-3.33.1-py3-none-linux_x86_64.whl`
   (і, якщо є, `station_val/` з кадрами станції).
2. Відкрити `train_colab.ipynb` у Colab, `Runtime → GPU (T4)`, **Run all**.
3. Усе пишеться **одразу на Drive** (`runs/ft_v2/`; 40 епох, ~9 хв кожна
   на T4). Після обриву сесії —
   знову **Run all**: клітинка навчання сама продовжує незавершений прогін
   з `last.pt`, пропускає завершений і починає новий, лише коли прогону ще
   немає.

Ноутбук рахує **точку відліку** (стара модель на новій валідації), донавчає,
порівнює «до/після», експортує `best.onnx` (640, opset 11), будує
калібрувальний набір і компілює HEF.

## 6. Калібрування і HEF

- **Калібрування** (`build_calib.py`): 1024 кадри з **train** (не з val —
  оптимізатор донавчає на них квантовані ваги), рівномірно за розміром
  дрона (<16 / 16–32 / 32–64 / ≥64 px) + фонові кадри станції; леттербокс
  до 640 сірим 114, RGB, 0..255 — рівно те, що `HailoInference` подає на чіп.
- **Компіляція** (`compile_hef.py`, DFC 3.33.1 — тим самим зібрано чинний
  HEF; на Pi HailoRT 4.23.0) — двічі:
  - `logits` — рецепт чинного `bestty_yolo260508.hef` (клас-виходи йдуть з
    чіпа логітами, sigmoid робить станція);
  - `sigmoid` — sigmoid на чіпі. Виміряно на Pi: у чинного HEF логіти
    класу квантовані кроком ~0.7–0.8, тож вище 0.4 він видає лише
    0.5 / 0.665 / 0.69 / 0.80 / 0.83 / 0.887 / 0.915.
- Скрипт **зупиняється**, якщо DFC понизив би рівень оптимізації (немає GPU
  або < 1024 кадрів — це видно лише в його лозі), або якщо виходи моделі не
  збігаються з `HEAD_CONFIG` (`bestty_yolo26/conv61…conv94`).

### Лише HEF, на іншому акаунті (скінчився безкоштовний GPU)

`hef_colab.ipynb` + `hef_only.py`: потрібні лише три файли в
`MyDrive/drone_hef/` іншого акаунта — `best.onnx`, wheel DFC і

тепер задають GPU явно.

## 7. Порівняння HEF на Pi

```bash
# на Pi, станцію зупинити (камери й Hailo — по одному процесу)
~/mk/venv/bin/python compare_hef.py --station ~/mk/acoustic_radar \
    --images val/images/val --hef old.hef --hef new.hef --order both --out r.json
~/mk/venv/bin/python capture_backgrounds.py bg --n 150     # фон зі станції
~/mk/venv/bin/python compare_hef.py --station ~/mk/acoustic_radar \
    --images bg --hef old.hef --hef new.hef --order bgr --out bg.json
```

`compare_hef.py` проганяє кожен HEF **через клас станції** `HailoInference`
(той самий леттербокс, декодування, NMS) і рахує AP50, recall/precision при
0.40 і 0.55, recall за розміром дрона, хибні бокси на кадрах без дрона і час
чіпа. `--order bgr` — те, що станція подає за замовчуванням
(`swap_detector_channels = False` віддає масив picamera2 «RGB888» як є).

Остаточна перевірка — живий дрон: на Pi з `"detection_log": true` запустити
стару й нову модель (`--hef`) на тому самому польоті.

## 8. Швидкість Hailo на Pi 5 (02.10.2026)

`hailortcli run -t 10`, станцію зупинено, Pi 5, HailoRT 4.23. Готові HEF
Hailo — model zoo **v2.18** (DFC 3.33.0 / HailoRT 4.23, як на Pi),
`hailo8l/yolo26n.hef`, `yolo26s.hef` (COCO, 80 класів).

| HEF | контексти | PCIe Gen 2 x1, FPS батч 1 / 2 / 8 | **Gen 3 x1**, FPS батч 1 / 2 / 8 |

| yolo26s Hailo | 4 | 23.2 / 31.5 / 43.9 | 41.7 / 58.6 / 84.8 |
